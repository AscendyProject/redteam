## What
In agent-pair mode, both the implementer (who writes the tests) and the code
reviewer (who judges them) are pointed at the project's `test_conventions_file`
so agent-pair tests are judged against the same conventions TDD-mode tests
already are. TDD mode is behaviour-identical.

## Why
`test_conventions_file` (declared in `.redteam/workflows/config.py` and
defaulted to `.redteam/docs/test-conventions.md`) was only wired into the two
TDD-only phase runners (`write_test.py` / `verify_test.py`). In the default
agent-pair mode neither runs, so the config key was dead: the implementer
authored tests with no knowledge of the project's test wiring, and the
reviewer had no conventions document to judge them against. A consumer repo
shipped a component that never mounted to production because three "tests"
passed while only grepping the source file as text. This PR closes the gap
(#160) for agent-pair, keeping TDD injection where it already lives.
