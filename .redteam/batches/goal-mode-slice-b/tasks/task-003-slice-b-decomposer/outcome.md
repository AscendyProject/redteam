# Outcome — Slice B: goal→task decomposer + cross-provider decomposition review

## Goal
A human-authored `goal.md` at a batch root is turned by a new generic decomposer
agent into a Slice-A-shaped, single-parent `goal.json` + one non-empty
`tasks/<id>/input.md` brief per task, then **adversarially reviewed
cross-provider** and **fail-closed gated** before any task state is seeded or any
task is run. Absent `goal.md`, the orchestrator is byte-for-byte unchanged from
the post-Slice-A/C baseline.

The subcommand reads `goal.md`, invokes the decomposer worker, writes `goal.json` + `tasks/<id>/input.md`, runs the cross-provider decomposition review, and **returns before any task is dispatched**. `start` / `resume` are not modified to auto-run decomposition — the operator runs `decompose` first, then `start`/`resume`.
- [ ] A new generic decomposer agent skeleton exists at `.claude/agents/goal-decomposer.md` with YAML front-matter using the `tools:` key (per #76; `allowed-tools:` is dropped silently).
- [ ] A new generic decomposer prompt exists at `.redteam/prompts/codex/goal_decomposer.md`, project-agnostic (no `Ascendy`, `ruff`, `pytest`, `mypy`, `app/`, `tests/api/`, `main...HEAD`, or other stack/project literals from the `_FORBIDDEN_IN_AGENTS` family).
- [ ] `.redteam/scripts/install.py` `HARNESS_AGENTS` includes `"goal-decomposer"` so the installer vendors the 7th skeleton; `test_install.py`'s `for name in install_mod.HARNESS_AGENTS` loop transitively asserts it.
- [ ] `.claude-plugin/marketplace.json` `plugins[0].agents` lists `./.claude/agents/goal-decomposer.md`, AND `.redteam/tests/test_plugin_packaging.py`'s `_EXPECTED_AGENTS` set is extended to include `"goal-decomposer"` (the current `<=` assertion permits supersets, but the explicit set is the documented packaging contract).
- [ ] `.redteam/tests/test_agents_generic_prompts.py`'s `_AGENT_FILES` list (currently 6) is extended to include `"goal-decomposer.md"` so the existing forbidden-literal guard runs over the new skeleton.
- [ ] **Idempotency mechanism is fail-closed-by-default (PR-003 settled — no `--force` flag in v1).** If `<batch>/goal.json` already exists OR any `<batch>/tasks/<id>/input.md` already exists, `decompose` aborts with a non-zero exit and a clear "already decomposed; remove generated artifacts manually to re-run" message; no file under `<batch>/` is written or modified on that abort. Re-decomposition requires the operator to manually delete the prior generated artifacts — this protects any human-edited file under `<batch>/`.
- [ ] **Decomposer worker contract is pinned in `phase_runners/decompose.py` (not just prompt prose) — the runner accepts EXACTLY one of three outcomes and fails closed on anything else:**
  (a) **success:** worker exit 0 AND `<batch>/goal.json` is present on disk AND for every task ID in `goal.json` the matching `<batch>/tasks/<id>/input.md` is present and non-empty → proceed to the cross-provider decomposition review;
  (b) **cannot-decompose:** worker exit 0 AND `<batch>/goal.json` is ABSENT AND the worker emitted `DECOMPOSE_DECISION: CANNOT_DECOMPOSE` as its final stdout line AND `<batch>/decompose_blocked.md` is present and non-empty → `cmd_decompose` exits non-zero, the blocked artifact is surfaced, and NO `goal.json` / `tasks/<id>/input.md` / `tasks/<id>/state.json` is written or modified;
  (c) **anything else** (non-zero worker exit, partial write — `goal.json` without all briefs or vice versa, no marker and no `goal.json`, unparseable output) → `cmd_decompose` exits non-zero, no review is invoked, and any partial files the worker wrote under `<batch>/` are left in place untouched for the operator to inspect (the runner itself writes/modifies nothing further). The contract lives in `phase_runners/decompose.py`; the prompt only echoes it.
- [ ] **Manifest/brief completeness gate (closes PR-004 blocker).** Before the cross-provider review is invoked AND again before `cmd_decompose` exits 0 on APPROVED, the orchestrator asserts that for every task ID in the generated `goal.json`, `<batch>/tasks/<id>/input.md` exists and is non-empty. Any missing or empty brief aborts the whole batch with a non-zero exit, surfaces which task IDs are missing briefs, and seeds NO `tasks/<id>/state.json`. This is a fail-closed pre-approval check in `cmd_decompose` — `_load_goal_manifest`'s body is NOT modified (its existing directory-only check stays as the load-time backstop; the new check sits in `cmd_decompose` alongside it).
- [ ] On a non-APPROVED decomposition review, `cmd_decompose` exits non-zero, persists the review artifact at `<batch>/decompose_review.md`, and seeds NO `tasks/<id>/state.json` (the per-task state-machine surface is untouched until APPROVED).
- [ ] On APPROVED, the generated `goal.json` is loaded through Slice A's existing `_load_goal_manifest` fail-closed validation (single-parent, no cycle, no unknown/self ref) AND Slice C's `ceilings.max_tasks` ceiling — **the exact same path** used today for a hand-fed manifest. No second/weaker validator is added.
- [ ] The decomposition review goes through `review_with_fallback` (the #37 fallback ladder + the existing reviewer adapters); no new reviewer transport, no revival of the rejected sub-agent reviewer path (`docs/decisions/2026-06-17-reviewer-transport-and-subagent.md`). Cross-provider invariant: the decomposition review reuses `_adversarial_pairing_error` / `reviewer_provider` / `worker_provider` rather than open-coding a second cross-provider check; a same-provider configuration refuses fail-closed.
- [ ] A new test file `.redteam/tests/test_goal_decomposer.py` (matching `test_*.py`) asserts, with the decomposer worker AND the reviewer adapter mocked/stubbed and no live model call:
  (a) an agent-generated `goal.json` that violates single-parent / has a cycle / has a self or unknown ref / exceeds `ceilings.max_tasks` aborts the WHOLE batch via the SAME Slice A+C `_load_goal_manifest` path (no `tasks/<id>/state.json` seeded, no task run);
  (b) **a generated `goal.json` whose task IDs are NOT all backed by a non-empty `<batch>/tasks/<id>/input.md` aborts the WHOLE batch fail-closed BEFORE any task state is seeded and BEFORE `start`/`resume` could ever return `no_input_md` for that task** — covers both the "missing input.md" and the "empty input.md" subcases, exercising the new pre-approval completeness gate above (PR-004);
  (c) a non-APPROVED decomposition review aborts fail-closed (no `state.json` seeded, no task run) AND `<batch>/decompose_review.md` is present;
  (d) the cannot-decompose contract: a stubbed worker that emits `DECOMPOSE_DECISION: CANNOT_DECOMPOSE` + writes `decompose_blocked.md` and NO `goal.json` causes `cmd_decompose` to exit non-zero, leaves the blocked artifact in place, writes NO `tasks/<id>/state.json`, and never invokes the reviewer; and a stubbed worker that exits 0 with NO `goal.json` AND NO `DECOMPOSE_DECISION: CANNOT_DECOMPOSE` marker is rejected fail-closed under outcome (c) of the runner contract;
  (e) an APPROVED decomposition (with a generated `goal.json` whose every task has a non-empty `input.md`) lets the existing layered scheduler run the validated stack on a subsequent `start`/`resume`;
  (f) absent `goal.md`, `decompose` is never invoked and `process_batch` / `_run_pipeline` behave byte-for-byte as under Slice A/C (a hand-fed `goal.json` runs identically);
  (g) re-running `decompose` against a batch that already has `goal.json` OR any `tasks/<id>/input.md` fails closed with a non-zero exit and writes/modifies nothing under `<batch>/`;
  (h) a same-provider worker/reviewer configuration refuses fail-closed via the existing `_adversarial_pairing_error` helper.
- [ ] No edits to `_ensure_task_branch`, the `base_branch` pin block in `process_task`, the centralized freeze guard / `pinned_base_branch`, the layered `_topo_layers` / `_run_batch` scheduler past the new `decompose` subcommand, `_load_goal_manifest`'s validation body, or Slice C's `max_tasks` enforcement (reuse only).
- [ ] Engine remains zero-runtime-dependency: no new non-stdlib `import` lines anywhere under `.redteam/workflows/` or `.redteam/scripts/`.

## Out of scope
- Multi-parent DAGs. v1 is single-parent only; the decomposer serializes-or-stops (no partial forest is ever seeded/run).
- Auto re-plan on a REJECTED decomposition (decision #3): the human edits `goal.md` and re-runs.
- A `--force` flag on `decompose` (PR-003 settled — fail-closed-by-default; operator manually removes prior generated artifacts to re-decompose).
- Auto-running `decompose` from inside `start` or `resume` (PR-002 settled — `decompose` is a distinct subcommand the operator invokes explicitly).
- Token / wall-clock ceilings — Slice C left them parse-tolerate; not enforced here.
- Any change to `_ensure_task_branch`, the per-task `base_branch` pin, the freeze guard, the layered scheduler, or `max_tasks` enforcement.
- Any change to `_load_goal_manifest`'s body. The new completeness gate (PR-004) lives in `cmd_decompose`, not inside `_load_goal_manifest` — Slice A's loader keeps its existing directory-only check unchanged, so the hand-fed manifest path is not regressed.
- The per-task `plan_review` phase — it still runs unchanged per task downstream; this slice adds a review one level UP (of the decomposition itself), not a replacement.
- Auto-merge or any change to the draft-PR / human-checkpoint flow downstream.
- A second, weaker manifest validation path that bypasses Slice A/C's `_load_goal_manifest`.
- Editing this repo's own `.redteam/docs/*` (project-owned, seeded once) or `.redteam/config.toml`.

## Risks
- **Slice B may need to sub-slice.** The brief flags that decomposer-generation and decomposition-review may not fit in one PR. This outcome covers Slice B as a whole; if `plan_review` splits the slice, the same Done-when items split along the gen-vs-review seam (the file budget already isolates them: `prompts/codex/goal_decomposer.md` + `.claude/agents/goal-decomposer.md` + `HARNESS_AGENTS` + `_AGENT_FILES` + `_EXPECTED_AGENTS` for gen; `phase_runners/decompose.py` review wiring + `decompose_review.md` artifact for review).
- **Re-decomposition friction.** Fail-closed-by-default means an operator who edits `goal.md` after a bad decomposition must `rm <batch>/goal.json <batch>/tasks/*/input.md` (or remove the batch's `tasks/` subtree) before re-running. Deliberate — protects any human-edited artifact from silent clobber and keeps v1 small; a `--force` flag can be added later if the friction proves real.
- **Untrusted agent output.** The decomposer is a model; its `goal.json` is adversarial input to the engine. It MUST flow through Slice A's `_load_goal_manifest` fail-closed validation + Slice C's `max_tasks` — reuse that exact path; the decomposition review does NOT replace it. A second, weaker validation path is the trap to avoid.
- **PR-004 completeness gate placement.** The gate sits in `cmd_decompose`, not inside `_load_goal_manifest`, so the hand-fed-manifest path (Slice A's existing directory-only check) is not regressed. If a future hand-fed user wants the same brief-completeness guarantee, that is a separate slice — surface in review if `plan_review` disagrees.
- **Cannot-decompose marker name.** Pinned here to `DECOMPOSE_DECISION: CANNOT_DECOMPOSE` and an artifact at `<batch>/decompose_blocked.md`. If `plan_review` prefers a different marker (e.g., reusing `REVIEW_DECISION: ASK_USER` semantics) the implementer updates both `phase_runners/decompose.py` and `test_goal_decomposer.py` together.
- **Project-agnosticism of the new prompt + skeleton.** The new prompt and agent body must embed no project/stack fingerprints (`test_agents_generic_prompts.py` guards this). The decomposer must reason about ANY `goal.md`.
- **Reviewer transport reuse.** Use the existing review adapter + #37 fallback ladder; do NOT revive the rejected sub-agent reviewer transport (`docs/decisions/2026-06-17-reviewer-transport-and-subagent.md`).
- **Decomposer-agent provider symmetry.** The decomposer is an untrusted worker; if the operator routes both worker and reviewer through the same provider family the decomposition review collapses to self-review and the slice's adversarial guarantee dissolves. The existing `_adversarial_pairing_error` / `reviewer_provider` / `worker_provider` helpers MUST be reused for this new review one-level-up — do NOT open-code a second cross-provider check.
- **Persisted-artifact paths** are pinned here to `<batch>/decompose_review.md` and `<batch>/decompose_blocked.md`. If `plan_review` prefers `<batch>/goal_review.md` and `<batch>/goal_blocked.md` (parallel to `goal.json`), the implementer updates `cmd_decompose`, `phase_runners/decompose.py`, and `test_goal_decomposer.py` together.
- **State-machine integration.** Because `decompose` is a separate subcommand (not a phase inside `process_task`), it lives entirely outside the per-task `state.json` machine — no new task-level phase, no new ordered-phase entry, no batch-level state file. If `plan_review` later wants an "already approved, skip" marker, that is a follow-up; v1 derives "already decomposed" purely from the presence of `goal.json` / `tasks/<id>/input.md`.
- **The `outcome-planner` Verification heading parser quirk** (separate, pre-existing latent bug) is unrelated to this slice; downstream phases must not be retrofitted as a workaround here — surface separately if it bites.
