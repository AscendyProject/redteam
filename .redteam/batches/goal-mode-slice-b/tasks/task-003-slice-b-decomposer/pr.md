## What
A human-authored `goal.md` at a batch root is turned by a new generic decomposer
agent into a Slice-A-shaped, single-parent `goal.json` + one non-empty
`tasks/<id>/input.md` brief per task, then **adversarially reviewed
cross-provider** and **fail-closed gated** before any task state is seeded or any
task is run. Absent `goal.md`, the orchestrator is byte-for-byte unchanged from
the post-Slice-A/C baseline.

## Why
Slice B is the last piece of the goal-mode design (#94, Piece 2), stacking on
Slice A (PR #111: single-parent manifest + layered scheduler) and Slice C
(PR #113: ceilings + goal-done criterion). The operator authors a one-file
`goal.md`; a decomposer agent generates the task forest the scheduler runs.
Because that forest is untrusted-agent output gating real work, it is a
safety-boundary change and must flow through the SAME Slice A+C validation as a
hand-fed manifest, plus an additional cross-provider adversarial review one
level up — never trusted on its own, never silently auto-running.
