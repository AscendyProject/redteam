## One gap your handoff didn't cover (worth noting for future consumers)

A consumer that was the **extraction origin** still carries the harness's own
unit tests (`.redteam/tests/`) and ran them via its test suite. After `--overwrite`
those old tests mismatch the new engine, AND the v0.1.0 tests can't pass in a
consumer anyway (e.g. `test_checked_in_config_toml_loads_and_validates` asserts
`name == "redteam"`, but a consumer's config is its own). So I removed
`.redteam/tests/`, dropped it from pyproject `testpaths`, and excluded `.redteam`
from ruff — a consumer lints/tests its own code, not the vendored harness.

**Suggestion for the redteam README / install docs:** state explicitly that
`install.py` intentionally does NOT vendor `.redteam/tests/`, and that a consumer
should not run the harness's self-tests (and should exclude `.redteam` from its
own linters). Only the extraction-origin consumer (backend) hit this because it
had inherited the tests; a fresh consumer never gets them — but documenting it
prevents confusion.

Also a tiny cosmetic: your shipped engine files are `ruff check`-clean but not
`ruff format`-clean (your verify.sh runs `ruff check .redteam/` but not
`ruff format --check`). Harmless for vendoring (consumers exclude `.redteam`),
but if you ever want consumers to lint the harness, add a `ruff format` pass to
your CI. Non-blocking.
